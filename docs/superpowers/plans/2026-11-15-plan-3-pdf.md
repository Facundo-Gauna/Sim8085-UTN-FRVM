# Plan 3 — Exportación a PDF y "Autocompletar observaciones"

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** El alumno genera en PDF, desde la web, las dos hojas de entrega de la cátedra (Plantilla Assembler y Plantilla Registros-Banderas-Memoria) con diálogo de datos, vista previa y paginación, y puede autocompletar las observaciones que le falten.

**Architecture:** Una función pura del núcleo (`describeInstruction`) produce el texto de las observaciones automáticas. En `packages/web/src/pdf/` un módulo de **maquetación pura** (sin dependencias de PDF; recibe una función `measure`) convierte filas del ensamblado o de la traza en páginas; **la misma maqueta** alimenta la vista previa HTML y el renderizador PDF (`pdf-lib`), así lo que se ve es lo que se exporta. El guardado de bytes va detrás de `FileService` (el plan 6 agrega la variante de Tauri).

**Tech Stack:** `pdf-lib` (PDF puro JS, sin DOM, igual en web y Tauri), React, Zustand, Vitest. Fuente del PDF: Helvetica estándar de PDF (sin incrustar fuentes; el PDF replica la plantilla oficial, no la identidad visual).

**Spec:** `docs/superpowers/specs/2026-11-15-simulador-8085-design.md` (§6.8, §6.1 contador, §8 "PDF generado por la app", §9.1 "los PDF no siguen la identidad visual"). Plantillas oficiales de referencia: `docs/referencia/Plantilla Assembler.pdf` y `docs/referencia/Plantilla Registros-Banderas-Memoria Assembler.pdf`. Núcleo: `ListingRow`, `buildTrace`, `TraceRow` (`packages/core`). Decisiones previas: `docs/superpowers/plans/2026-11-15-plan-1-decisiones.md` (las etiquetas locales ya vienen sin `@n` en `ListingRow.source`).

## Global Constraints

- Solo español; terminología del manual y de las plantillas ("Dirección", "Mnemónico", "OP.CODE", "Observación", "Posición de Memoria", "Valor en Memoria", "Ins. N°", "Registros", "Banderas", "Hoja Nº", "Alumno", "Ejercicio", "Fecha").
- PDF Assembler: **un byte por fila**; mnemónico solo en la fila del primer byte; el OP.CODE de cada fila es ese byte en hexa de 2 dígitos mayúscula; Dirección en hexa de 4 dígitos con `h` (`2000h`). Encabezado "ARQUITECTURA DE COMPUTADORAS / Alumno / Ejercicio / Hoja Nº", barra negra y fila de títulos, **repetidos en cada hoja**; Nº de hoja automático.
- Observación = el comentario `;` de la línea (`ListingRow.comment`), **tope de 80 caracteres**; si es más largo se recorta a 77 + `...` y la vista previa lo marca. Se ajusta dentro de la celda a un máximo de 2 renglones; en una instrucción de 2 o 3 bytes el segundo renglón ocupa la celda de Observación de la fila del byte siguiente; en una de 1 byte esa fila se hace del doble de alto. Una fila nunca se parte entre hojas.
- PDF Registros-Banderas-Memoria: **una fila por instrucción ejecutada** (`buildTrace`), tope **500 filas** con aviso si se supera (`TraceResult.truncated`); columnas Posición de Memoria (`2000h`), Valor en Memoria, Ins. N°, A B C D E H L M (hexa de 2 dígitos), Z P S CY (0/1) con el valor **después** de cada instrucción; Posición y Valor vacíos si la instrucción no accede a memoria. Su encabezado es el de la plantilla: "ARQUITECTURA DE COMPUTADORAS / Alumno / Hoja N° / Fecha" (la plantilla no tiene "Ejercicio"; el ejercicio va en el nombre del archivo y en el título del documento).
- Hoja A4 vertical, márgenes de 32 pt, **44 filas de datos por hoja**, alto de fila 15,5 pt, Helvetica 9 pt para datos. Proporciones de columnas (fracción del ancho útil): Assembler 0,118 / 0,316 / 0,168 / 0,398; Registros 0,17 / 0,13 / 0,07 / 8 × 0,05 / 4 × 0,0575.
- Todo texto que llega al PDF pasa por `pdfSafe`: Helvetica solo codifica WinAnsi, por lo que `←` → `<-`, `↔` → `<->`, `→` → `->`, tabulaciones → espacio y cualquier otro carácter no codificable → `?`. Nunca debe lanzar por un carácter raro.
- Los archivos se nombran `<ejercicio>-assembler.pdf` / `<ejercicio>-registros.pdf` (sin caracteres inválidos; si el ejercicio está vacío, `programa`).
- El simulador exige `asm.ok === true` y la sesión no `stale` para exportar o autocompletar; si no, el botón queda deshabilitado con el motivo visible (no un error al hacer clic).
- UI con los tokens de `design-system/MASTER.md`; el diálogo es una región de la página (nunca `alert`/`confirm`), con foco atrapado, Escape que cierra, y etiquetas accesibles; la vista previa respeta tema claro/oscuro pero **dibuja la hoja en blanco y negro** como el PDF.
- No se agrega persistencia: los datos del diálogo (Alumno, etc.) solo viven mientras la página está abierta.

## Review Focus

1. **Texto raro en el comentario** (`←`, emoji, tabulaciones, acentos, comillas tipográficas): el PDF se genera igual, sin excepciones y sin caracteres rotos para `á é í ó ú ñ º °`. → Task 3 y 4.
2. **Observación de exactamente 80 y de 81 caracteres**, y palabra sin espacios más larga que el renglón: 80 entra sin marca, 81 se recorta y se marca; nunca se desborda la celda. → Task 3.
3. **Programa con bucle infinito o muy largo en la traza**: `buildTrace` corta a 500 filas y el diálogo avisa "se muestran las primeras 500 instrucciones"; un error de ejecución (opcode inválido) se informa y el PDF incluye las filas previas. → Task 5.
4. **Alumno o Ejercicio con texto muy largo, vacíos o con caracteres raros**: el encabezado recorta con `...` dentro de su celda, vacío se imprime en blanco, y el nombre de archivo se sanea. → Task 3 y 4.
5. **Paginación en el borde**: justo 44 filas = 1 hoja; 45 = 2 hojas con encabezado repetido y Hoja Nº 1, 2; una fila de doble alto que no entra pasa entera a la hoja siguiente; `Hoja Nº inicial` distinta de 1 numera desde ese valor. → Task 3.

**Interfaces:**

- Produces: `export function describeInstruction(row: ListingRow): string | undefined` — texto en lenguaje simple, ≤ 80 caracteres, `undefined` si `row.instr` no existe (datos `DB`/`DW`).

Reglas de redacción (usar `←` y los nombres del manual; `r` = registro, `rp` = par `BC` `DE` `HL` `SP` `PSW`; `M[HL]` es el byte apuntado por HL; el dato inmediato y las direcciones se muestran en hexa con `h` en minúscula y 2 o 4 dígitos **tomados de `row.bytes`**, salvo que el operando fuente de una dirección sea una etiqueta (empieza con letra, p. ej. `LOOP`): entonces se muestra el nombre):

| Familia | Texto |
|---|---|
| `MOV d,s` | `d ← s` (`M` se escribe `M[HL]`): `A ← B`, `A ← M[HL]`, `M[HL] ← B` |
| `MVI r,d8` / `LXI rp,d16` | `B ← 05h` / `HL ← 1234h` (en `MVI M`: `M[HL] ← 05h`) |
| `LDA a` / `STA a` | `A ← M[2000h]` / `M[2000h] ← A` |
| `LHLD a` / `SHLD a` | `HL ← M[a]` / `M[a] ← HL` |
| `LDAX rp` / `STAX rp` | `A ← M[BC]` / `M[BC] ← A` |
| `XCHG` / `XTHL` / `SPHL` / `PCHL` | `HL ↔ DE` / `HL ↔ tope de la pila` / `SP ← HL` / `PC ← HL` |
| `ADD r` `ADC r` `SUB r` `SBB r` | `A ← A + r` / `A ← A + r + CY` / `A ← A - r` / `A ← A - r - CY` |
| `ANA` `ORA` `XRA` | `A ← A AND r` / `A ← A OR r` / `A ← A XOR r` |
| `CMP r` / `CPI d8` | `A - r (solo cambia banderas)` |
| `ADI ACI SUI SBI ANI ORI XRI` | igual que su forma con registro pero con el dato inmediato: `A ← A + 05h` |
| `INR r` `DCR r` | `r ← r + 1` / `r ← r - 1` |
| `INX rp` `DCX rp` `DAD rp` | `rp ← rp + 1` / `rp ← rp - 1` / `HL ← HL + rp` |
| `RLC RRC RAL RAR` | `rota A a la izquierda` / `a la derecha` / `rota A a la izquierda por CY` / `... derecha por CY` |
| `CMA CMC STC DAA` | `A ← NOT A` / `CY ← NOT CY` / `CY ← 1` / `ajuste decimal de A` |
| `JMP a` / `CALL a` / `RET` | `salta a a` / `llama a a` / `vuelve de la subrutina` |
| `Jcc a` `Ccc a` `Rcc` | `si Z = 0, salta a a` (idem llama / vuelve). Condiciones: `NZ` `Z = 0`, `Z` `Z = 1`, `NC` `CY = 0`, `C` `CY = 1`, `PO` `P = 0`, `PE` `P = 1`, `P` `S = 0`, `M` `S = 1` |
| `RST n` | `llama a 0018h` (n × 8) |
| `PUSH rp` / `POP rp` | `pila ← rp` / `rp ← pila` |
| `IN p` / `OUT p` | `A ← puerto 05h` / `puerto 05h ← A` |
| `EI DI RIM SIM NOP HLT` | `habilita interrupciones` / `deshabilita interrupciones` / `A ← máscara de interrupciones` / `máscara de interrupciones ← A` / `sin operación` / `detiene el procesador` |
